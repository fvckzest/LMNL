# Domain docs

This is a single-context repository.

## Before exploring

- Read `CONTEXT.md` at the repository root.
- Read any ADR in `docs/adr/` that touches the area being changed.
- If an expected file or directory does not yet exist, proceed without treating its absence as an error.

## Language

Use the canonical terms defined in `CONTEXT.md` in issue titles, specifications, code, tests, and user-facing explanations. Avoid synonyms that the glossary explicitly rejects.

If the required concept is missing or conflicts with existing language, use the domain-modeling process to resolve and record it before treating the term as settled.

## Decisions

Surface any conflict with an existing ADR explicitly. Create ADRs only for decisions that are hard to reverse, surprising without context, and the result of a genuine tradeoff.
